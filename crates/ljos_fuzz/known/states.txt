# Buckets of ljos-fuzz states that are known: as known/bindings.txt, one per line, the
# signature then why.
# Triaged from seeds 101 and 202 (2000 cases each).

# The order of a state change (features/states/state-change-order.feature) is fixed; these
# buckets still come up in seeds 101 and 202 for other differences, not yet triaged.
value:onChanged:text      Qt tells more changes: NaN bound again through Qt.binding (features/language/nan-is-a-change.feature), and a PropertyAction with no value, told three times
value:load:number      an int a state's change gives text that is no number, or a state that changes a property the item lacks
value:step:invalid-ljos      a state's own change makes its when false, without a transition: Qt stays in it, Ljós goes to the default state
value:step:invalid-qt      a when a set of another property makes true again: Qt enters its state anew
value:step:text      a when that turns true again while a state given by name is in force: Qt goes to its state, Ljós stays
warning:assign(ljos-only):QML_Case:_Unable_to_assign_*      a change of a real to undefined, or of a colour to an object, is warned of by Ljós only
warning:assign(qt-only):Unable_to_assign_QJSValue_to_int      an int declared with an array, among states and transitions, is warned of by Qt only
warning:binding-loop(ljos-only):*      a change that reads a property whose own binding reads the changed one is a loop to Ljós only
warning:binding-loop(qt-only):load      NaN given to a NaN is a change, so a change giving it NaN through a binding of it is a loop (features/language/nan-is-a-change.feature)
warning:binding-loop(qt-only):step-set      a change of a property that reads it is a loop to Qt when it gives NaN or a colour

# Qt's own quirk, which Ljós is not to copy: a `when` that a change of its state makes false
# again, while a transition runs, sends Qt back to the default state with a warning that it
# cannot apply a state change within one; Ljós stays in the state, or stops the loop and says so.
value:step:empty-ljos      a when its own state makes false: Qt leaves the state partway, Ljós settles
value:step:empty-qt      a when its own state makes false, with a transition: Qt goes back to the default state
warning:binding-loop(qt-only):when      a when its own state makes false is a loop to Qt
warning:other(qt-only):<Unknown_File>:_QML_StateGroup:_Can'      Qt cannot apply a state change within one
warning:other(ljos-only):QML_State:_property_"_"_handlers_re-ran_N_times_in_one_update      a when its own state toggles: Ljós stops the loop and says so
